## Coding Style: Match Codebase

Minimize friction. Before writing code, observe the nearby project conventions and make your changes feel native to the existing codebase, even when those conventions are imperfect.

Follow the dominant local style for:
- naming, file structure, imports, formatting, and TypeScript usage;
- component, hook, service, controller, store, and helper patterns;
- async flow, error handling, state conventions, API shapes, and domain vocabulary.

Keep diffs short, readable, and localized:
- change only the lines needed for the task;
- avoid cosmetic edits, broad reformatting, import churn, module reshaping, and unrelated renames;
- do not move code, reorganize files, or replace established patterns without a direct need.

Prefer consistency over theoretical perfection:
- use existing helpers, types, abstractions, and return shapes when they fit;
- preserve the surrounding abstraction level;
- do not introduce factories, wrappers, generic helpers, classes, or extra layers unless the project already uses that approach or the task clearly requires it.

Respect existing tools and dependencies:
- run or follow configured formatters and linters when relevant;
- if no tool is clear, imitate the surrounding style;
- do not add dependencies for convenience unless they already exist, the user requested them, or the benefit is necessary and local.
