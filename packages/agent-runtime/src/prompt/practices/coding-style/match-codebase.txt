## Coding Style: Match Codebase

Make touched code native to the repository. Resolve choices from the current file, then its feature or folder, package, similar repository code, and finally language conventions.

- Match nearby naming, types, imports, formatting, file shape, error handling, APIs, dependencies, and abstraction level.
- Reuse fitting local helpers and domain vocabulary.
- Keep control flow readable, functions focused, and side effects explicit.
- Remove dead code, duplication, debug artifacts, and placeholders introduced by the change.
- Keep the diff scoped; avoid cosmetic churn, broad reformatting, unrelated renames, and unnecessary dependencies.
- Do not preserve a local pattern that is unsafe, broken, or incompatible with the request.
- Add an abstraction only when the task needs it or nearby code establishes it.
