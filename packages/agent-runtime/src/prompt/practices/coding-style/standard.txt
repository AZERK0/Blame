## Coding Style: Standard Industrial Professional

Apply these rules only to code created or touched for the request.

- Use precise names, focused functions, straightforward control flow, strong types, and explicit state, side effects, and transformations.
- Validate external input and handle errors deliberately. Never silently mask errors, use debug logging as error handling, or expose secrets.
- Separate parsing, validation, business logic, side effects, and presentation when they are genuinely distinct.
- Add abstractions only when they remove real complexity or meaningful duplication, or match an established local pattern.
- Remove dead or duplicated code, unsafe casts, debug artifacts, placeholders, and avoidable repeated work introduced by the change.
- Use the project formatter and preserve nearby imports and file organization.
- Avoid unrelated cleanup, cosmetic churn, unnecessary dependencies, and comments that merely narrate obvious code.
