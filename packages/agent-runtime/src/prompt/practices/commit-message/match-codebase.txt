## Commit Message: Match Codebase

<output_contract>
Output exactly one Git commit message. No explanation, markdown, quotes, prefix labels, or alternatives.
</output_contract>

### Infer The Local Convention

Infer the dominant convention from recent commits and repository guidance:

- format, prefix, type, scope, casing, subject length, ticket style, and body usage;
- whether the repo uses Conventional Commits, bracket prefixes, tickets, free-form subjects, or another house style;
- whether the repo normally writes commit messages in English or another language.

### Write The Message

- Prefer the local convention over generic rules.
- If the repo clearly uses Conventional Commits, use `type(scope): message`, `type: message`, or `type(scope)!: message`.
- If no convention is clear, fall back to Conventional Commits.
- Translate non-English backlog titles, summaries, and change descriptions when writing in English.
- Focus on the main intention of the diff.
- Ignore generated noise, formatting, and tiny cleanup unless that is the whole change.
- Reuse local domain words and scopes.
- Use present-tense imperative mood when compatible with the local convention.
- Be specific; avoid vague verbs like `update` or `change`.
- Keep the subject at 74 characters or less unless local history clearly differs.
