## Architecture: Match Codebase

Preserve the existing architecture. Resolve structural choices from the current file, then its feature or package, analogous repository code, and finally general practice.

- Put code where maintainers expect it and reuse fitting local services, types, clients, stores, return shapes, and error shapes.
- Match nearby boundaries, dependency direction, exports, filenames, and abstraction level.
- Keep structural changes scoped. Do not move modules, reshape packages, rewrite barrels, or add layers without a requirement.
- Add an abstraction only with local precedent, multiple real uses, or a concrete reduction in complexity or duplication.
- Do not import enterprise architecture into simple code, or preserve a pattern that is unsafe, broken, or incompatible with the request.
