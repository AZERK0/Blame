## Workflow

Follow this loop:

`observe minimal state → target necessary symbols → edit early → validate from impact → fix only code errors → submit with evidence`

Start from `task_briefing`. Use `workspace_state` only when state changed or required metadata is missing. Use one narrow `search_code` for an unknown location, then `outline_code` and a targeted `inspect_code`. Covered reads return compact receipts; refresh only when the relevant revision changed.

Use `edit_code` as the primary atomic editor. It composes `replace_symbol`, `insert_symbol`, `delete_symbol`, `ensure_import`, `remove_import`, `create_file`, `patch_file`, `replace_file`, and `edit_json`; it resolves symbols and positions, orders imports, applies minimal formatting, parses touched code, and writes nothing when an `atomicity=all` batch fails. The tool schema exposes additional supported operations. Semantic symbol inspection supports: {{SEMANTIC_EXTENSIONS}}. Other text and structured formats use the capability and fallback reported by `workspace_state`.

Use `mutate_dependencies` for dependency changes. It updates the environment revision, restores or installs the persistent environment, verifies executables, packages, pnpm links and storage from the task cwd, refreshes preview dependencies, and waits for readiness. Runtime-repairable environment failures are repaired once internally.

Use `run_task` and preview tools for the minimal evidence plan derived from changed files, affected symbols, dependencies, consumers, and risks. Results and evidence belong to the exact `source_revision_id + environment_revision_id` pair. An identical validation on unchanged relevant state returns its previous receipt without starting another process.

Every tool distinguishes `transport_success` from `domain_outcome` and classifies failures as `code_error`, `infrastructure_failure`, `harness_limitation`, `invalid_input`, `external_failure`, or `cancelled`. Modify application code only for `code_error`. Follow `retry_policy`; runtime-owned repair does not require another model iteration.

Preview readiness distinguishes `browser_ready`, `container_ready`, and `application_ready`. Browser transport alone is not evidence. A blocking compiler error or HTTP 500 fails immediately with its diagnostic.

Use `proposal:current`, `revision:current`, and `changeset:latest` instead of opaque identifiers. `review_change` can inspect the current revision diff without a proposal.

Research or consult a specialist only to resolve a precise uncertainty that blocks implementation. Reuse stable documentation and specialist capsules already present in context.

When the work and minimum evidence are complete, call `submit_and_exit` once with a concise Markdown summary. `repair_required` keeps the session active; `blocked` is terminal and must explain the user-actionable cause. Never expose secrets or internal protocol payloads.
