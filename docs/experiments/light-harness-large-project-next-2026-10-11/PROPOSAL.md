Proposed next benchmark: real multi-file issues (not executed or preregistered task selection)

The complete date-fns project contains about 98k TypeScript source lines, yet the completed panels supply implementation paths and often need one short edit. T5 reference/native conditional token savings of 34–40% do not isolate semantic navigation, and F6 fresh confirmation has wide reference/native intervals. A larger repository is not sufficient evidence.

Use a public real-issue panel such as SWE-bench Verified. Select issue IDs from the complete eligible population with a fixed seed before any model trials, stratify by repository and preregister all IDs, eligibility rules and environment exclusions. Include issues requiring inter-file discovery; do not feed implementation paths, gold patches, tests containing the solution, grader source or retrieved solutions to agents. Do not change selection because of model results. A Python panel tests language-specific adapters too; never pool it with TypeScript date-fns campaigns.

Preparation required before calls:

- Read and verify permitted issue data and immutable source/environment versions; prepare official evaluator containers and positive/pristine negative controls. Current runner needs an adapter; no issue assets or official Docker evaluation were prepared in this study.
- Freeze Blame reference, exactly one modified mechanism, integrated Cline SDK, full prompts/schemas, model/provider/effort, tool/environment identities, source, dependency locks and evaluator hashes. Keep tool-capability differences explicit.
- Configure a named USD/time/token campaign budget before launch; execute serial balanced order with matched repetitions and watchdogs. The next panel has no configured model budget or executed trials yet.
- Keep diagnostics separate from unseen confirmation. For an information or navigation intervention, record whether returned information is actually exposed/used and whether its source coverage affects editing authority.

Report official issue resolution, independently audited complete criteria without solution retrieval, tests actually executed/passed and admitted verification separately. Preserve failures, timeouts, exclusions chosen before results, incomplete request/cache accounting and all raw events/source diffs. Pair resources only within matched audited-completion cohorts, while retaining whole-panel totals and missingness. Count input/output once; cached input and reasoning are subsets, not additional tokens. API-estimated cost is not an invoice. Separate runner, outer execution, setup and evaluator time. Use repository/task-cluster uncertainty, and require a prespecified quality-compatible success or resource gate rather than choosing a favorable metric afterwards.

Decision after a completed confirmation: retain a mechanism only for the effect supported by its controls and exposed trials, abandon it on predefined regressions, or deepen if effects are unexposed/uncertain. No finite panel proves that all improvement margin is exhausted.
