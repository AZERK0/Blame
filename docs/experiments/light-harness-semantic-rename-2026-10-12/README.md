# F10: guarded compiler-derived rename

This is a separate intervention after F9 identity navigation. F9's correct optional backend worsened model token/cost/time totals against prior Light; see its separate archived diagnostic. F10 compares the exact frozen F9 runtime against F9 plus native rename and integrated Cline SDK 0.0.82, on the same three prespecified known date-fns requests. They are diagnostics, not unseen confirmation. `protocol.json` was registered before implementation or F10 model outcomes.

## Implemented contract

The five Light primitives remain. `edit_code` accepts one symbol operation with action `rename` and the new identifier in `content`. The complete target declaration must have been read and remain fresh. The existing TypeScript 5.9.3 worker resolves compiler rename locations, excluding arbitrary string/comment matching and preserving explicit aliases/shorthand public keys. It rejects invalid/escaped names, name capture/member collisions, incomplete configurations, ambiguous JS/TS source shadows, external source locations, overlapping locations and more than 50 changed files. Related identifier edits are mechanically derived, not model-generated replacements of unseen bodies. Existing body-replacement observation requirements remain unchanged.

The worker never writes source, runs plugins or emits code. An in-memory overlay compares before/after syntactic and semantic diagnostics in changed files, rejecting additional diagnostics and retaining pre-existing errors. This is a bounded static guard, not behavioral equivalence, test execution, admitted verification or user acceptance. Required actual compiler/tests must run after editing. The 12-second rename worker deadline and existing heap/read budgets include cold graph creation. No persistent cache or file-index intervention is bundled.

Exact compiler source/configuration/dependency footprints are rechecked during planning and before commit. Generated byte edits use the existing preimage/revision, syntax, durable journal, commit and recovery path. Concurrent source changes abort; this is not physical atomicity across every uncooperative external process. Unsupported/partial projects block native rename with explicit guidance; no silent lexical global replacement occurs.

## Local evidence

`local-replay.json` records successful native renames on pinned date-fns `313b902b9a72c64501074db9bc2b9897d2db5140`: each touches 10 files, passes the independent lexical identifier-only oracle, actual `npm run types` and all seven requested existing test files (136 passed, one skipped). Initial single local operations take 4.2–4.6 seconds; the final replay takes 4.1–6.6 seconds while other local checks overlap. Fresh worker creation is included, filesystem/cache and load are uncontrolled, and these are not controlled model efficiency gains. Original sources and assertions are not repaired by the supervisor.

Fourteen dedicated native controls within 349 focused runtime/provider tests pass; changed-module ESLint and runtime compilation pass. Controls cover observation/staleness, alias/homonym identity, unaliased imports/calls, shorthand/re-export aliases, UTF8/BOM, invalid/escaped identifiers, capture/member collisions, incomplete/missing configuration, 50-file bound, concurrent caller changes, cancellation, no-op, pre-existing diagnostics and JavaScript without granting unseen-body coverage. Packaged runtime tests execute native rename through the actual shipped worker and persisted observation path. All three actual packaged tests pass; see verification logs for exact counts. No local mechanism result substitutes for the registered model comparison.

## Completed F10 diagnostic

All nine registered trials complete with 3/3 official, independent and audited completions per arm, actual required agent checks and no solution retrieval. Final diffs are byte-identical across arms and to F9's mechanical endpoint; the runtime is separately frozen. Native rename is actually used once on each cross-file task and never on the local control.

Versus F9, the observed panel saves 3.9% tokens, 28.7% estimated cost and 29.5% runner time. Versus Cline it saves 32.3%, 45.0% and 20.0%, respectively. Output tokens fall 53.2% against F9, consistent with avoiding model-generated multi-file patches; input changes only slightly. These are summed matched-panel observations, not proof that every trajectory difference is causal or that population performance improves. Three-task exploratory token-ratio intervals versus F9 span 0.653–1.677; all resource ratios preserve their broad intervals.

Adverse outcomes matter: the timezone task uses 20.0% more tokens than F9 despite lower estimated cost; the unused local control uses 67.7% more tokens and about 95.0% more estimated cost. A scoped export-prefix patch is blocked before the model corrects it. Models still issue redundant searches and misinterpret scope `*`; native rename alone does not remove navigation friction. Targeted project-test verification can remain `unknown` even when the actual requested tests exit successfully; neither a static guard nor unknown scope is relabeled as admitted test evidence. Actual agent checks, technical admission and independently audited criteria stay separate.

Tokens/cost reconcile in 9/9, complete per-request cache accounting in 0/9. Observed aggregate cache reads are 116,224 / 116,224 / 158,720 tokens (subsets of input); missing request fields and hidden retries remain unestablished. `checks.json`, `summary.json`, `paired-comparison.json`, `source-review.json`, `inventory.json` and 54 unchanged raw artifacts retain all outcomes. `pre-confirmation-budget-analysis.json` preserves the precise pre-review accounting snapshot used by the subsequent shared-budget reservation.

Decision: **keep guarded native rename for its correct local contracts and observed diagnostic efficiency**, while retaining the adverse controls and rejecting a global-superiority claim. A separately preregistered new-request confirmation compares combined F9+F10 to original prior-production Light and Cline. Future priorities are clearer scope/route presentation, honest validation obligations, and broader language/graph coverage; each requires a separate intervention or confirmation.
