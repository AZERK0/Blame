\begin{abstract}
Improve independently assessed task success and truthful results first;
compare tokens, cost and duration only at comparable quality. Blame's Light
harness provides five core primitives with syntax-aware navigation, guarded
edits and runtime-owned completion. It does not provide compiler reference
resolution or general acceptance proofs. Historical performance remains
mixed. This follow-up verifies historical diagnoses against current code,
adds bounded arguments to catalogued test tasks, and runs a separately
registered three-arm pilot. A further reliability experiment isolates
bounded recovery of noninteractive provider interruptions. Mechanical evidence and model outcomes are
reported separately; neither constitutes a global superiority claim.
\end{abstract}

Tool assembly is in \code{light-tools.ts}, with finish assembled separately.
\code{LightWorkspace} coordinates navigation, aliases, coverage, edits,
commands and journal persistence. The \code{LightWorkspaceExecutor} port
carries the same operations, metadata and cancellation to managed execution.
Configured preview, skills, MCP or specialist tools may supplement the five
primitives. Native Cline SDK tools are a separate runtime configuration.

Syntax adapters use ast-grep/Tree-sitter and report whether they actually
load. An alias identifies an observed declaration using path, qualified name,
byte ranges and hashes. A unique unchanged target may relocate after a
neighboring edit; ambiguity or changed observed content requires a fresh read.
Coverage is consumer/context-generation specific. Compaction does not create
observation of source bytes it merely mentions.

\code{LightCommitService} checks workspace revision and file preimages,
writes a durable pending record and applies individual atomic writes.
Recovery preserves a conflicting third-party state instead of overwriting it.
Cooperating readers use the same lock. This is recoverable batch behavior,
not isolation from all editors, processes or external services. Post-commit
receipt failures identify an already-applied effect; blindly repeating that
edit is unsafe.

\code{workspace-command-process.ts} bounds capture, drains inherited output
for a bounded interval and terminates process groups on abnormal interruption.
Intentional detached services may survive normal parent exit. Running handles
are session-local memory, not restart-persistent processes. The benchmark
runner separately bounds abort, usage collection and shutdown. Command policy
uses actual isolation/managed-preview metadata; it is not a universal shell
sandbox.

The stable provider projection preserves previously sent blocks while the
canonical prefix remains unchanged. Canonical resets/compaction create a new
basis. Responses function schemas default to \code{strict: false} so optional
arguments stay optional; local schema validation still applies. Context bytes
are not billed tokens. Project memory uses bounded retrieval and current
file hashes; no longitudinal benefit is established by this pilot.

\subsection{Validation is deliberately conservative}
Keep four distinct claims: tests executed, tests passed, validation admitted,
and user criteria satisfied. \code{observeCheck} records process state,
counts/outcome, scope, selection, freshness and evidence origin. Interrupted
green output, zero tests and silent exit-zero runs cannot establish passing
tests. Managed pytest, VSTest and Surefire reports are invocation-attributed;
old reports are not discovered as new evidence.

Tests with a passing observed outcome still have unknown selection and,
without detected changes, unknown freshness. The task runner records their
validation status as unknown. They do not promote delivery to verified.
Failed tests remain failed. Builds/typechecks can supply admitted source-based
coverage; that does not mean behavioral tests or user criteria passed.
The journal requires matching source revision and covered file hashes.
Environment revision hashes Node manifests/lockfiles, not installed tools,
runtime variables, services or the full execution environment, and is not
bound as a complete validation provenance record.

The default session contract stores the objective as free-text criteria and
sets \code{effect_requirement: none}. Explicit \code{source_change} contracts
require an effect, but default acceptance does not prove an implementation
request was fulfilled. \code{harness-core} exports richer authorities,
evidence-planner and transaction contracts; the Light finish path does not
invoke that evidence planner. Core lifecycle integration and shared types do
not imply integration of the historical four-authority protocol.

\section{Testable priorities and implemented intervention}
\paragraph{H1: separate test identity from arguments.}
Cause: arguments in IDs cause refusals or force shell fallback. Compare frozen
reference Blame, modified Blame and integrated native Cline. Measure actual
argv use, task-selection refusals and audited success first; then resources.
Risks are argument order, package-manager forwarding and conflating a filtered
check with full-scope validation. Shell fallback remains possible in all arms,
so H1 is an interface-friction hypothesis, not a claim of previously impossible
capability.

Implemented: optional \code{args}, at most 32 nonempty strings of at most
2,048 characters, excluding NUL. Pass them as literal argv after the declared
native invocation or package script; npm receives its \code{--} separator.
Only test tasks accept nonempty extra arguments, to avoid admitting a filtered
build as full coverage. Defaults, task identity and scripts remain unchanged.
Journal records retain argv and distinguish selections: a passing selected
run cannot erase a known full-suite failure. Test proof remains unknown.
Filtered pytest currently falls back from its strict managed-report adapter;
full invocation-attributed pytest remains available. Maven/.NET adapters
retain their existing reporting behavior. No general scope proof is added.

\paragraph{H2: explicit proof admission, proposed only.}
Cause: useful passing observations remain unknown; source equality does not
identify the execution environment or test selection. Compare the current
conservative policy with one isolated provenance/admission change, first in
replays with stale source, changed dependencies, interrupted output and scoped
checks. Measure false verified and false unknown decisions, then audited task
success. Risk: false assurance from external writers, missing dependencies or
unproven scope. Do not restore the archived obligation solver or infer user
acceptance from a test count. H2 is not implemented in this campaign.

\subsection{Decision and next experiments}
Retain the bounded test-argv interface for its demonstrated contract behavior
and actual use, without claiming an improvement in task success or overall
efficiency. Local tests find no introduced source regression; the model
campaign's adverse outcome and measurement gaps remain material. Abandon the
automatic Vitest rewriting proposal in the tested noninteractive setting.
Deepen H1 on new, preselected Maven/.NET/Node repositories requiring test
filters; measure refusals and fallback recovery before optimizing tokens.
Use new confirmation tasks, not these now-familiar diagnostics.

Next, investigate the shared transport's socket closure and final-iteration
stall separately, preserving bounded cleanup and interrupted usage. Then
implement one H2 admission mechanism in an isolated test environment, with
explicit invocation, source, installed environment and selection scope;
keep arbitrary user acceptance distinct. Add a behavioral acceptance fixture
like the intermediate CSV counterexample before any stronger verified claim.
Compiler/LSP references, broader read-granularity changes and memory ablations
remain lower priorities until a concrete current failure and representative
confirmation tasks justify them. No longitudinal memory, cross-platform,
large external-repository or new Terminal-Bench confirmation was executed.

\section{Follow-up: noninteractive transport recovery}
\subsection{H3 and implemented mechanism}
The follow-up reference is \code{c103d04b}, retaining the argv improvement;
the isolated intervention is \code{23b454d5}. Do not pool it with the first
pilot. The observed socket failure motivated H3: a bounded recovery could
improve audited delivery after transient transport failure without changing
ordinary model inputs, tool schemas or acceptance admission.

The current runtime already recovers one recognized interruption in an
interactive session. Its original noninteractive path deliberately stopped
instead: SDK 0.0.82 destroys that session when its run ends, so calling
\code{send} on it cannot implement recovery. Light automatic development
now restarts the same session from canonical persisted messages and compaction
state, with the original config and a recovery instruction. It subtracts
observed consumed iterations from the original maximum and offsets subsequent
iteration events; the benchmark's original wall deadline is retained.
Initial attachments are not emitted again. Native Cline retains its existing
behavior, as do non-Light sessions without \code{finish_task}.

Recovery is refused for permanent provider errors, unknown/exhausted iteration
budgets, cancellation, active tools, submitted completion and a second
interruption. Every observed completed tool ID must have its result in the
persisted history; missing history or a missing result prevents a model call.
Cancellation is checked again after asynchronous history loading. This guards
against restarting with unknown prior effects; it does not make arbitrary
external commands idempotent or prove that the model will never repeat an
action. The existing journal, command and edit policies remain in force.

Ten added runtime tests exercise history/effect retention, remaining budget,
event numbering, single recovery, permanent errors, native-control exclusion,
active tools, cancellation during history loading and missing receipts.
The targeted runtime/runner selection passes 102/102. The entire runtime
package selection passes 671 tests with two existing environment/platform
skips; the previously reproduced formatter failure is excluded separately.
Three accounting/injection tests pass; compilation and changed-file ESLint pass.

\subsection{Diagnostic preflights and fixed confirmation panel}
Real-SDK preflights on the known freshness task found no treatment activation
from either a single before-body cut or a 64-byte-prefix cut: both controls
and modified completed. Source inspection of \code{@cline/llms} establishes
three internal attempts for classified network interruption before converted
model output. A separate three-attempt outage burst then produced failure
in reference and Cline, and one successful restart in modified. All nine
preflight trials remain diagnostics and are kept separately from confirmation.
The fault protocol was amended before any confirmation trial, retaining its
task selection, repetitions, arms and budgets. See \code{preflight-amendment.json}.

The frozen confirmation protocol is under
\filepath{docs/experiments/light-harness-recovery-2026-10-09/}.
Four existing corpus tasks, not used to select H3, are fixed:
\code{window-boundaries}, \code{slug-contract}, \code{stable-pagination}
and \code{webhook-idempotency}. They are not claimed historically unseen.
Two repetitions, three arms and two conditions give 48 trials, at most
816 iterations and 16,560 agent seconds. The configured model/effort,
SDK, fixture, prompts, schemas, lockfile and compiled versions are recorded
before execution; no replacement trials or solution retrieval are allowed.
The per-trial SDK estimated-cost limit is USD 0.05 and the panel stops starting
trials at USD 2.40 observed reported cost. These post-request estimates do not
constitute invoice caps, particularly when usage is interrupted.

The controlled condition interrupts three consecutive actual upstream response
bodies beginning with model request three, then restores healthy transport.
It exhausts the SDK's pre-output retry policy and tests the additional runtime
mechanism. Credential/auth calls are excluded by model-input matching.
The discarded upstream bodies may have incurred unreported usage; preserve
that missingness even when event and SDK counters reconcile. Ordinary runs
are reported separately; their reconciliation is between observable SDK events
and aggregates, not an invoice audit or proof that hidden provider retries
incurred no charge. Cache missingness remains independent.

Primary outcomes are audited obligations in each condition, with runtime
termination, scorer results and admitted verification separate. The combined
panel has a fixed 50\% interruption weight; it is not an estimate of ordinary
outage frequency or population performance. Compare resources only at
comparable audited quality. Retain the mechanism only if recovery improves
the interrupted pairs with no observed ordinary quality regression, and
inspect completed tool inputs/diffs for lost or repeated effects.

\section{Reproduction and evidence map}
Build core, model catalog, runtime (including prompt-resource copy) and
benchmark runner with the pinned workspace toolchain. The worker's global
pnpm was 11.19.0 and attempted an incompatible automatic install; the successful
build used the already installed TypeScript compiler directly. No repository
dependency or lockfile change was needed. Freeze the built reference checkout
with \code{node tools/terminal_bench/corpus/light-study.mjs freeze baseline},
then the intervention checkout with \code{freeze modified}; both snapshots
share unchanged core/dependency packages. Use \code{run} once, then
\code{analyze}. Run \code{light-study-audit.mjs}, review its candidates and all
traces, save adjudication, then use \code{light-study-publish.mjs} to export
unchanged compressed traces/diffs and their inventory. Direct replay uses \code{light-study-replay.mjs} with a compiled
runtime directory and output JSON. Existing corpus preparation, scoring and
headless CLI are reused. Runtime artifacts and raw events stay under
\code{.blame/research}; compact results, hashes and review evidence accompany
the protocol as \code{results.json}, \code{summary.json},
\code{adjudication.json}, \code{tool-ledger.json} and \code{inventory.json}. Credentials are never archived.
The follow-up uses the same driver with \code{BLAME_STUDY_DIRECTORY} pointing
to its registered directory and \code{BLAME_STUDY_WORK_DIRECTORY} pointing
to a new workspace-artifact root. Freeze from each built checkout before
\code{run}. Its experimental \code{light-study-fault.mjs} preload is used
only in controlled trials, never imported by production.
