\begin{abstract}
Prioritize independently audited task success and truthful delivery, then compare
resources at comparable quality. Current Light combines syntax-aware navigation,
configured JS/TS compiler identity and guarded edits behind five primitives.
Historical success rates and incomplete accounting do not describe current code.
The new F28 study completes 108 fixed trials; its six-change guidance bundle
has no demonstrated net advantage over reference Light. F29 completes 18 trials:
phrase ranking improves retrieval but loses audited behavioral acceptance, so it
is not promoted. Supplementary counterexamples expose passing-test false positives
without repairing sources or rewriting frozen grades. F30 completes 27 trials on
a new project: shorter descriptions fail both registered quality/resource gates.
F31 completes 18 fixed trials on two public feature requests in two further
projects. It does not meet the quality/resource gates and never exercises the
changed whole-symbol route. Retain a locally verified indentation repair; keep
the validation-summary prototype isolated after neutral recorded-log replay and
added CPU work. Neither establishes a model gain.
F33 repairs misleading project-command display and corrects an earlier audit
inference: those historical tasks already used npm wrappers and lifecycle hooks.
No population superiority or exhausted improvement margin is established.
\end{abstract}

\section{Scope, versions and evidence boundaries}
This compact report separates implemented behavior, historical measurements,
new measurements and proposals. Expanded phase-by-phase notes are preserved
verbatim, with byte/hash inventory, in
\filepath{docs/experiments/light-harness-study-history-2026-10-15}.
Original campaign artifacts remain separate. Neither dependent repeats nor
local replay cases count as independent real-issue confirmations.

F28--F31 use \code{openai-codex}/\code{gpt-5.6-luna}/\code{high} and
integrated Cline SDK 0.0.82 with a pinned research search repair. This is not
an unmodified CLI comparison. Actual schemas, prompt sources, model/effort,
source/checker/environment hashes, ordered assignments and budgets are retained.
Light emits seven tools in these runs: five harness primitives and optional
skills/web support; native emits five. Normalized contracts are not literally
identical dynamic prompts. Checkout labels and review are unblinded; provider
revision/seeds and complete cache/invoice accounting remain unknown.

Four claims remain distinct: tests executed, tests passed, verification admitted
for a source/environment/scope, and satisfaction of user criteria. A process exit
or model summary alone proves neither the latter two nor an exhaustive test run.
Unknown counters are not zero; pending, skipped and runner-specific todo labels
must not be silently interchanged. Raw recorded output need not be model-visible.

\section{Next hypotheses: proposals, not measurements}
\begin{enumerate}
\item Confirm edit mechanisms on new exposed tasks in larger projects without
file-level localization hints. Preserve free tool choice; record absent exposure
instead of forcing a favorable route. Compare reference, modified and native
with repeated preregistered assignments, full/source acceptance and resources.
Risks include over-constraining tasks and attributing model variance to a repair.
\item Test invocation-bound validation presentation on fresh tasks. F33 controls
establish actual npm wrappers, lifecycle hooks and truthful argv display; do not
repeat the disproved direct-script diagnosis. Isolate dependent command ordering
and multi-stage summaries separately. Then isolate presentation
in a model comparison, measuring factual delivery and acceptance before resources.
Preserve unknown counts and execution/admission/user-criteria distinctions.
Extra context, CPU and false confidence from fragments are regression risks.
\item Test bounded read-only dependency declaration access through configured
compiler resolution. Compare existing shell fallback with otherwise identical
navigation on new cross-file/dependency tasks. Measure correct identity, repair
calls, audited acceptance and resources; preserve protected edit boundaries.
Risks are extra context, version confusion and unintended scope expansion.
\end{enumerate}
Each future phase must freeze prompts, schemas, model/effort, versions,
environment, task selection and budgets; keep known diagnostics separate from
fresh confirmation. Positive and adverse results must both remain visible.
Finite trials cannot demonstrate that no improvement margin remains.
