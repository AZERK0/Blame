# Corpus applicatif externe — protocole avant essais agents

Cette campagne est distincte de Terminal-Bench V10b. Elle conserve uniquement Luna high ; aucune mesure Sol ni mémoire projet. L'architecture et les cinq primitives de Blame restent inchangées. Le bundle de Blame comprend la récupération déterministe du mode commande (`727a3f4d`) et est construit au commit `e723fd40`. L’adaptateur de ce commit conserve Node/npm du projet et lance le SDK avec son Node privé. Le hash exact du bundle est inscrit au manifeste avant tout appel modèle ; Cline utilise le même runner avec le prompt et les outils natifs SDK 0.0.81.

Les six réservations proviennent de Multi-SWE-bench-flash et SWE-Sharp-Bench, à révisions et fichiers enregistrés. Sélection par métadonnées avant lecture des solutions. Le cas Avalonia sans FAIL_TO_PASS a été remplacé avant toute exécution agent, selon le classement enregistré. Aucun remplacement guidé par une performance agent. Les éventuels environnements inexploitables restent documentés et ne deviennent pas des échecs du modèle.

Admissibilité avant agents : image finale construite, matériel de référence et historique futur retirés, test de base exécuté avec au moins un test officiel requis réellement en échec, tous les PASS_TO_PASS conservés, aucun test requis absent ; correction officielle permettant de réussir tous les FAIL_TO_PASS et PASS_TO_PASS. Un timeout ou une exception du vérificateur n'établit pas ce contraste. La réussite de l'intégralité de la suite est rapportée séparément de celle du sous-ensemble officiel. Le parseur C# conserve un échec même si une autre occurrence de la même méthode réussit ; son écart au parseur upstream est documenté.

Chaque tâche admissible est exécutée deux fois avec chaque harness, soit quatre essais par tâche. Groupes de trois tâches au maximum : six essais par lot, deux conteneurs agents simultanés. La seconde répétition inverse groupes, tâches et ordre des bras. Aucun retry ni choix du meilleur résultat. Les jobs s'arrêtent en cas de lot incomplet ou entièrement interrompu avant agent. Aucun autre conteneur de benchmark ou contrôle de référence simultané aux essais agents.

Budgets communs : 4 CPU, 8 Gio de RAM, 64 itérations modèle, 900 secondes d'exécution agent, 1800 secondes de vérification. Le délai interne du runner inclut sa création de session. Le lanceur utilise un Node privé compatible avec le SDK et conserve les exécutables Node/npm déjà présents dans le projet. Les commandes Blame gardent leur délai de 120 secondes et Cline leurs délais natifs ; ceci compare les configurations livrées, pas une ablation à délais de commandes égaux. Les contrôles utilisent ces mêmes ressources, Node 22.23.2 pour le runtime, le Node fourni par le projet lorsqu’il existe, et, pour C#, .NET 8 / Linux sur les projets unitaires sélectionnés.

Les instructions agents ne contiennent que les issues originales. L'agent dispose du dépôt entier, sans localisation ajoutée ni indication de fichiers de solution. L'usage des symboles est libre. Les tests cachés sont injectés après l'arrêt de l'agent ; les patchs de référence ne sont jamais injectés dans ses conteneurs. Les fichiers de tests existants concernés sont restaurés au commit de base enregistré avant application du patch officiel. Un audit distinct vérifie les accès aux oracles et la modification du vérificateur ; les correspondances de motifs seules ne valent pas preuve de contamination. Les résultats officiels, les résultats audités et les tentatives suspectes restent distingués.

Le bilan principal garde les échecs. Il rapporte réussite, temps agent, requêtes, outils, types d'édition, rejets et durée du vérificateur. Les consommations exactes et coûts estimés du SDK sont limités aux tâches dont les deux harness et les deux répétitions ont une consommation complète et réconciliée. Les valeurs manquantes restent inconnues. Comparaison par tâches entières, bootstrap descriptif de 20000 tirages (graine 20260908), résultats par répétition et sensibilité au retrait d'une tâche. Aucun mélange avec Terminal-Bench ni sélection des seules réussites communes dans le résultat principal.

Couverture : un cas React en JavaScript, un cas Vue en TypeScript, deux réservations Java et deux C#. Deux références touchent plusieurs fichiers de code, sans imposer aux agents de reproduire leur patch. Ce corpus ne prouve pas un avantage sur les monorepos en général, Prisma, les autres frameworks .NET ni une User Story visuelle complète. Les cas restent publics et peuvent avoir figuré dans l'entraînement du modèle.

Les six tâches réservées sont admissibles après les contrôles : base 0 / référence 1, sans test officiel requis manquant. Material UI conserve sept échecs annexes avec la référence ; son score officiel et la réussite de toute la suite restent distincts. Jib nécessite une acceptation explicite du changement des métadonnées Origin/Label de son dépôt APT signé ; le premier build échoué est conservé. Aucun patch source ni test attendu n’est modifié pour cette réparation d’environnement.
