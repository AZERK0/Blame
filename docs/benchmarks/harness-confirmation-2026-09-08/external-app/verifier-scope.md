# Préparation du vérificateur applicatif

Aucun essai agent n’a commencé à ce stade. Le corpus utilisera les issues originales, une localisation ouverte dans les dépôts et les patchs de tests officiels injectés seulement après l’arrêt de l’agent. Les patchs de référence restent dans un stockage privé distinct, utilisé exclusivement pour contrôler l’évaluateur.

Le script partagé est `tools/terminal_bench/external/grade.py`. Il restaure les chemins de tests à partir d’un commit de base enregistré hors de la portée de l’agent, applique le patch officiel, exécute la suite, et rapporte séparément la réussite des tests officiels requis et celle de toute la suite. Une absence de tests, un test requis manquant, ignoré ou en échec, et un timeout ne valent jamais réussite. Les changements de l’agent sont enregistrés avant réinjection des tests. Cela ne dispense pas d’un audit de contamination ou de modification de l’environnement.

Neuf tests locaux couvrent notamment le remplacement frauduleux d’un test existant, la correction réelle du programme, les résultats incomplets, les délais et les résultats C# contradictoires. L'audit conserve aussi les changements déjà committés ou indexés, ainsi que les noms des fichiers non suivis. Les tests cachés et leur parser sont transmis uniquement par l’étape `Verifier.verify` de Harbor.

Les parseurs TypeScript et Java sont extraits sans modification fonctionnelle de [Multi-SWE-bench](https://github.com/multi-swe-bench/multi-swe-bench/tree/24f493f8a103e72312ded4f6b9c89f081d69cb09), sous licence Apache-2.0. Leur équivalence a été vérifiée sur cinq logs préliminaires ; ces logs ne remplacent pas les contrôles sur les images finales.

Le [parseur C# upstream](https://github.com/microsoft/prose/blob/50cc38f602fffe14073953cf128825ea8d92b188/misc/SWE-Sharp-Bench/harness/swe_sharp_bench/log_parsers.py) écrase un échec par le dernier résultat d’une méthode. Le replay synthétique publié montre ce défaut. Le corpus lit les mêmes noms TRX, mais conserve tous les échecs et ignore aucune occurrence contradictoire. Cette adaptation est déclarée ; les résultats ne sont pas présentés comme ceux du leaderboard upstream exécuté à l’identique.

Les contrôles C# ciblent l’intégralité des projets unitaires concernés sous .NET 8 / Linux. Les autres frameworks du dataset ne sont pas couverts. Les images applicatives conservent Node/npm du projet lorsqu'ils existent ; le runner utilise Node 22.23.2 dans son répertoire privé. Les premières images vérifient Material UI sous Node 18.20.7 et Vue sous Node 20.19.0. Le commit original du code, le commit local de base et l’identifiant de l’image sont enregistrés séparément. Toute image dont le contrôle de base et la correction officielle ne distinguent pas le défaut sera écartée avant les appels modèle, avec son motif conservé.
