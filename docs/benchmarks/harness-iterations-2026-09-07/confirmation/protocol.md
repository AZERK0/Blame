# Frozen confirmation protocol

Thirty-six trials: nine tasks, two harnesses, two repetitions. The candidate archive comes from the completed V2 diagnostic campaign and is verified against that manifest; native Cline SDK 0.0.81 uses the same archive's runner, transport and telemetry, its native prompt and native tools. This is not the latest standalone Cline extension.

Six unseen tasks were selected at 14:06 UTC before V1 results by the archived SHA256 ordering and category quotas in holdout-selection.json: regex-chess, circuit-fibsqrt, overfull-hbox, compile-compcert, sparql-university, sanitize-git-repo. Three prior diagnostic tasks remain: cancel-async-tasks, query-optimize, polyglot-rust-c. No substitution after seeing outcomes. The previously viewed tasks and benchmark solution files are never supplied to the measured agents.

Six groups of six trials, two concurrent Docker trials, one attempt, zero retries. Model openai-codex/gpt-5.6-luna, high reasoning, 64 iterations, nominal runner timeout 900 seconds after session creation; Harbor separately enforces each official task agent timeout (750–3600 seconds in this sample). The adapter forwards the configured runner timeout without rewriting the official task limits. Official CPU, memory and verifier limits are unchanged and identical across arms. BLAME_ISOLATED_ENVIRONMENT=true describes the existing Docker isolation. Three task blocks are reversed for repetition two, as are task and arm orders. Harbor may interleave tasks within a group. Any infrastructure failure stays in the original data and score. No changes to bundles, tasks, adapter, model settings or resource limits during the campaign.

Primary measures are official success, elapsed agent-execution seconds, input plus output tokens including cached input, and provider-reported cost estimates. Also record request count, blocked edit calls, tool counts, cache tokens, setup/verifier times and errors. Missing usage is unknown, not zero. Do not compare exact global token or cost savings when either arm has incomplete usage. Give complete-block comparisons separately, with the selection bias explicit. Preserve all failed attempts and their observed consumption; do not report only successful trials.

Report both repetitions, the fresh subset, known diagnostics, per-task pairs and totals. Use task-cluster bootstrap intervals with both repetitions kept together, fixed seed, and leave-one-task-out sensitivity; nine tasks are nine clusters, not 36 independent observations. Bootstrap intervals on this deliberately stratified small sample are descriptive uncertainty, not population-wide guarantees. Joint-success resource pairs are secondary and selected on success.

The intended outcome is at least as much task success with lower time and token use, without higher cost. A stable global gain cannot be claimed from one favorable total, a single outlier, selected successes, missing usage or an infrastructure failure in the comparator. Repetition disagreement and leave-one-task-out reversals must be reported. A failure to establish this outcome is a valid campaign result; do not continue selecting runs until significance appears.

Review tool traces for oracle/verifier access before reporting audited rewards. Path scanners identify candidates, not proof; project tests and installed-library tests are distinct from privileged benchmark material. Analysis remains outside measured containers. Save raw traces locally and commit protocol, hashes, per-trial measurements and compact analyses on main. Candidate corrections during any later iteration require another frozen archive and separate campaign, preserving this one.

Native per-command policies are intentionally retained: Cline SDK 0.0.81 defaults to 30 seconds and has no model-facing timeout input in run_commands; Blame run_task defaults to 120 seconds. The model sometimes emits an undeclared timeout field that the Cline tool parser discards. This is a harness/tool difference, not identical command budgets. Report timeout-affected trials explicitly, and do not attribute their effects to token projection or editing. A future equal-command-budget control would be a separate intervention, not a rewrite of this native comparison.
